# AI-Powered Multi-Platform Grocery Shopping Agent

An asynchronous conversational grocery-shopping agent built with LangGraph, LangChain, Groq, and Model Context Protocol (MCP). It connects an LLM to two grocery data sources:

- **Swiggy Instamart MCP** for authenticated Swiggy grocery tools.
- **Local Zepto MCP server** implemented with FastMCP and Playwright.

> **Important:** This project accesses third-party services. Use it only where permitted by their terms, respect rate limits, and never commit credentials, access tokens, OTPs, or personal address data.

## Features

- Natural-language grocery search from an interactive terminal.
- MCP tool discovery through `langchain-mcp-adapters`.
- Swiggy Instamart OAuth authentication using PKCE.
- Local Zepto price and availability scraping with Playwright.
- LangGraph orchestration and conversation history during the current run.
- Utility script for checking the addresses available to the authenticated Swiggy account.

## How it works

1. `app.py` starts the interactive terminal application.
2. `model.py` initializes Groq's `llama-3.1-8b-instant` model using `GROQ_API_KEY`.
3. `mcp_client.py` connects to the local Zepto MCP server over stdio and Swiggy Instamart at `https://mcp.swiggy.com/im` over HTTP.
4. MCP tools are loaded and bound to the LangGraph agent.
5. The agent selects an appropriate tool for the user's request.
6. Tool results are returned to the model and printed in the terminal.

## Requirements

- Python 3.10 or newer is recommended.
- A [Groq API key](https://console.groq.com/keys).
- A Swiggy account and phone number that can complete OTP authentication.
- Internet access.
- Chromium installed for Playwright.

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/Ankita-aa/AI-Powered-Multi-Platform-Grocery-Shopping-Agent.git
cd AI-Powered-Multi-Platform-Grocery-Shopping-Agent
```

### 2. Create and activate a virtual environment

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Windows Command Prompt:

```bat
python -m venv .venv
.venv\Scripts\activate
```

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirement.txt
pip install requests
python -m playwright install chromium
```

On minimal Linux installations, you may also need:

```bash
python -m playwright install-deps chromium
```

## Configure `.env`

Create `.env` in the repository root. The file is ignored by Git and must never be committed.

```env
# Required by model.py
GROQ_API_KEY=gsk_your_groq_api_key_here

# Generated by get_swiggy_token.py
SWIGGY_ACCESS_TOKEN=your_swiggy_access_token_here
```

| Variable | Required | Description |
|---|---:|---|
| `GROQ_API_KEY` | Yes | Groq API key used by `ChatGroq`. Create one at <https://console.groq.com/keys>. |
| `SWIGGY_ACCESS_TOKEN` | Yes for Swiggy MCP | OAuth access token sent to Swiggy as a Bearer token. |

The code loads these values with `python-dotenv`, so run commands from the project root or ensure `.env` is located in the current working directory.

## How to get the Swiggy MCP server key

This project does not use a manually created static “server key.” It needs a temporary **Swiggy OAuth access token**, stored as `SWIGGY_ACCESS_TOKEN`.

The repository includes `get_swiggy_token.py`, which completes the OAuth authorization-code flow with PKCE.

### Step 1: Start the token helper

From the repository root, with the virtual environment active:

```bash
python get_swiggy_token.py
```

The script will:

1. Generate a temporary PKCE verifier and challenge.
2. Open the Swiggy MCP authorization page.
3. Ask you to authenticate with your Swiggy phone number and OTP.
4. Ask you to paste the **full redirected callback URL**.
5. Exchange the authorization code for an access token.
6. Append `SWIGGY_ACCESS_TOKEN=...` to `.env` automatically.

The callback configured by the script is:

```text
http://localhost:8000/callback
```

When prompted, paste the complete URL from the browser address bar, including its query string. It should contain a `code` parameter. Do not paste only the OTP, only the domain, or an incomplete URL.

### Step 2: Verify `.env`

After successful authentication, `.env` should contain values similar to:

```env
GROQ_API_KEY=gsk_...
SWIGGY_ACCESS_TOKEN=...
```

The token is sensitive and temporary. The helper currently reports an expiry of approximately five days. Run the helper again when the token expires or when Swiggy rejects it.

### Step 3: Test Swiggy authentication

```bash
python get_addresses_id.py
```

This calls Swiggy's `get_addresses` MCP tool and prints the addresses associated with your account. Do not share this output because it may contain personal information.

## Configure the local Zepto MCP server

Open `mcp_client.py` and replace the machine-specific path in the `zepto` configuration with the absolute path to this repository's `server.py`.

Windows example:

```python
"args": [r"C:\path\to\AI-Powered-Multi-Platform-Grocery-Shopping-Agent\server.py"],
```

macOS/Linux example:

```python
"args": ["/path/to/AI-Powered-Multi-Platform-Grocery-Shopping-Agent/server.py"],
```

The client uses `sys.executable`, so the server runs with the Python interpreter from the active virtual environment.

The Zepto scraper currently opens Chromium in non-headless mode and uses the hard-coded location `Wakad Pune`. Change the location logic in `server.py` if required. Since the scraper depends on Zepto's web page structure, selectors may need updates if the website changes.

## Run the application

After setting both environment variables and configuring the Zepto path:

```bash
python app.py
```

Example requests:

```text
You : Search for rice and compare the available grocery options.
You : Find milk and show the prices available near me.
You : Which grocery items are available on Zepto?
```

Exit with `exit` or `quit`.

## Troubleshooting

### `GROQ_API_KEY` is missing

- Confirm `.env` is in the project root.
- Confirm the variable is named exactly `GROQ_API_KEY`.
- Run the application from the repository root.
- Create a key at <https://console.groq.com/keys>.

### `SWIGGY_ACCESS_TOKEN is missing`

Run `python get_swiggy_token.py`, complete OTP authentication, and confirm that the script appended the variable to `.env`. Restart the application after changing `.env`.

### Swiggy token is rejected or expired

The token is temporary. Run the token helper again. The Groq key and Swiggy token are different credentials and cannot be substituted for one another.

### Authorization callback does not contain a code

Paste the full redirected URL, not just the authorization page URL. If the callback contains an `error` parameter, restart the authentication flow.

### `Unable to connect to MCP Servers`

Check that the Swiggy token is valid, the Zepto `server.py` path is correct, the virtual environment is active, Chromium is installed, and both third-party URLs are reachable.

### `ModuleNotFoundError`

```bash
pip install -r requirement.txt
pip install requests
python -m playwright install chromium
```

### Zepto returns no products

The scraper currently searches in `Wakad Pune` and depends on Zepto's current HTML structure. Verify the location, browser, and item availability, then update `server.py` selectors if the website has changed.

## Security notes

- Never log or upload tokens, OTPs, addresses, or callback URLs.
